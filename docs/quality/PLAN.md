# V0.1 Development Plan

This plan preserves the ten macro Changes in Spec Baseline §32. It is planning only; no Change has been proposed or applied. Every Change must enter through OpenSpec and may cover only its own scope. Requirement and Acceptance mappings are baseline targets and may be refined without changing requirement strength.

Every `SCOPE_GUARD` Requirement is a global Change gate. A proposal must show that it does not introduce a prohibited capability, but Scope Guards are not presented as the primary business outcome of any Slice. `ROLLUP` and cross-stage `E2E` Requirements remain `UNIMPLEMENTED` until their complete Acceptance can run; partial implementation never earns PASS.

## Test layers and evidence policy

| Layer | Purpose | Required use |
|---|---|---|
| STATIC | format, lint, typecheck, schema validation | Every Change where applicable |
| UNIT | state transitions, scoring, hashing/cache, filters, parsing, deterministic rules | Every affected rule |
| INTEGRATION | API/service/worker persistence behavior | Real PostgreSQL; SQLite cannot substitute for final PostgreSQL verification |
| CONTRACT | OpenAI/Embedding/MediaCrawler boundaries | Deterministic fixtures and provider/adaptor contracts |
| E2E | Web → API → PostgreSQL user paths | Prefer Playwright |
| LIVE_INTEGRATION | Real MediaCrawler platform and real LLM provider | Controlled runs in the accepting Change; missing login/credentials/environment = `BLOCKED` or `NOT_VERIFIED` |
| MANUAL | Only behavior not reasonably automatable | Must retain named evidence |

Mock results never satisfy `LIVE_INTEGRATION`.
