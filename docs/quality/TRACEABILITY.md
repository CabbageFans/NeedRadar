# Traceability Matrix

This matrix originates from the Requirement Index generated by `scripts/quality/check_quality_docs.py --write-traceability`. Each Requirement has exactly one row. Result policy follows D-015 and the canonical verification-scope registry: `UNIMPLEMENTED` means the Requirement is not yet implemented, is only partially implemented across a Slice/Change boundary, or the active Slice lacks `FULL` completion authority. `IMPLEMENTED_UNVERIFIED` is a controlled transition that requires the active Change/Slice to be the canonical `FULL` owner and the Evidence cell to reference exactly one valid Implementation Attestation binding the Requirement, required Acceptance IDs, implementation/test refs, structured pytest node metadata, successful fresh canonical target execution, receipts, and current source fingerprint. The checker revalidates every existing IU on every run with no persisted-state exception; a manually written/orphaned intermediate state is invalid. `PASS` requires the same attestation recorded in the committed `IMPLEMENTED_UNVERIFIED` pre-state plus separate Requirement Verification evidence whose canonical targets are freshly executed, with matching attestation hash, unchanged sources, and every canonically required Acceptance proven. Manifest command/exit-code/log/reviewer claims grant no machine authority. Reviewer independence is guaranteed by the separate verification process, not by editable repository metadata.

Result enum: `UNIMPLEMENTED`, `IMPLEMENTED_UNVERIFIED`, `PASS`, `FAIL`, `BLOCKED`, `NOT_APPLICABLE`.

Completion reports must separately show: (1) all Requirements, (2) mandatory `ATOMIC` Requirements, and (3) `ROLLUP`/`E2E` gates. Partial work never promotes a full Rollup/E2E Acceptance.
